# Obsidian library migration (X01)

Status: converter, fixture coverage, and local Worker/D1 validation passed on October 2, 2026. Actual-vault review and migration remain pending.

## Purpose and boundary

Convert a local Markdown article folder used by the preserved prototype into the service's version-2 portable import format. This is an offline, read-only converter. It never starts the prototype, loads `.env`, contacts a service, modifies the vault, or retires the old workflow. The owner reviews the report before using Settings → Import. Existing normalized URLs retain their current service data under the existing import contract.

The command is `pnpm obsidian:convert --source /absolute/path/Articles --output /absolute/path/new-output-directory`. Output is required and must be a new directory outside the source tree; its existing parent must resolve outside the vault. It contains `report.json` and sequential, compact `import-001.json` files bounded to the API's 1 MiB/1,000-record limits. An empty conversion produces a report and no batches. Refuse existing output destinations, including symlinks, and avoid overwriting files. Operational failure exits nonzero; individual excluded files are expected report results. Stdout gives counts only. Reports and batches contain private library information and should be kept private.

## Discovery and parsing

Recursively inspect `.md` and `.markdown` regular files, ordered by relative path. Do not follow symbolic links or inspect hidden directories such as `.obsidian` and `.git`. Report skipped symlinks and per-file failures without abandoning otherwise valid files. Use strict UTF-8 decoding and a 1 MiB per-file read bound, with an overall bounded scan (64 MiB of Markdown and 10,000 candidate files); exceeding aggregate limits aborts rather than publishing a partial conversion. Read source files only. Use filesystem metadata observed during the scan; do not invent dates from the conversion clock.

Recognize an initial YAML frontmatter block, optionally preceded by a UTF-8 BOM, terminated by a standalone `---` or `...` line. An unterminated block, invalid YAML, duplicate YAML keys, custom tags, aliases (including unused aliases), or unsupported mapped metadata is a per-file error. Parse safe YAML scalars and sequences with pinned `yaml` 2.8.1; do not evaluate code or expand aliases. Keep the Markdown body verbatim after removing just the frontmatter block (including its closing line ending). Preserve Unicode and body line endings. Unknown metadata fields may be ignored; reject unsupported shapes for fields used in the conversion. This deliberately avoids importing the prototype module, which starts a server and loads environment variables.

## Mapping and review policy

- Source URL: require a single nonempty `source` scalar (or one-item scalar sequence). Use the service's URL normalization policy: absolute HTTP(S), no embedded credentials, at most 8 KiB UTF-8; strip fragments and tracking keys only from the deduplication key. Do not guess a source URL from arbitrary links in the article body. Missing and invalid URLs are separate report categories.
- Title: nonempty `title`, otherwise the first Markdown H1, otherwise basename without extension and the prototype's leading `YYYY-MM-DD. ` prefix. Enforce the service's 500-character bound rather than silently truncating.
- Author/description: accept optional scalar description and scalar or flat sequence authors; normalize Obsidian `[[name|label]]` author links and join multiple authors with `, `. Quote wiki-link scalars in YAML sequences (for example, `- "[[Ada Lovelace]]"`); an unquoted flow form such as `author: [[Ada Lovelace]]` parses as a nested sequence and is excluded as unsupported metadata. Enforce the existing 200/500-character bounds. Explicit null or absent optional metadata becomes null.
- Created date: use a valid `created` value; otherwise a valid leading filename `YYYY-MM-DD.` date; otherwise observed filesystem modification time. Accept a real calendar date as midnight UTC or an ISO timestamp with an explicit timezone, and canonicalize to UTC milliseconds. Invalid explicit dates exclude the file; do not silently fall back. `updatedAt` is the later of observed modification time and `createdAt`. Ignore `published`, which is not the saved date.
- Read state: recognize explicit booleans and the prototype's scalar equivalents (`true`/`yes`/`1`, `false`/`no`/`0`, case-insensitive). Missing, null, or unknown `read` values exclude the file for review. A true flag requires a valid explicit `readAt` timestamp with timezone; a missing/invalid date excludes the file rather than manufacturing a read time. A false flag requires absent/null/empty `readAt`; a conflicting timestamp excludes it. Date-only `readAt` is ambiguous and is excluded.
- Markdown copy: preserve a nonempty body with `source: "upload"` and `capturedAt: createdAt`; derive a stable revision from the body hash. This capture time is migration metadata representing the source's saved date, not evidence of an original browser capture. Empty bodies import link metadata only and produce a warning. Bodies above 256 KiB UTF-8 exclude the file, with a size-limit reason. Local attachments and Obsidian wiki links remain literal Markdown; assets are not copied, and the service reader's existing image limitations apply.
- IDs: derive a deterministic namespaced SHA-256 ID from the normalized URL, within the service's 128-character limit. Repeat conversion produces stable IDs and revisions; timestamps in the envelope may differ.
- Portable record sizing: exclude a single record whose JSON escaping makes it exceed the import envelope, even when its Markdown body is under 256 KiB. Abort the whole conversion if aggregate scan or final backup limits are exceeded.
- Duplicates: the first eligible file in sorted relative-path order wins. Later eligible files with the same normalized URL are excluded and report the winner's relative path. Never merge conflicting bodies or read states. Ineligible files do not claim a URL. Repeat import uses the existing skip-existing-URL policy.

The report records each candidate's relative path, outcome, reason(s), warnings, and the chosen date source; duplicate entries identify the winner. It reports discovered, eligible, duplicate, excluded, read/unread, copied/link-only, and batch counts so totals reconcile. Do not put body content or auth data in the report. An input folder failure or unsafe output destination must not emit import files. Generate and validate every batch before publishing output; clean up newly created partial output on failure.

The `scripts/obsidian-convert.mjs` command writes compact version-2 import batches and a report, using the shared backup validator/splitter. Ten temporary-vault unit tests cover source-byte checks, strict YAML/date handling, tracking duplicates, JSON escaping limits, hidden directories/symlinks, output safety, and unquoted wiki-link author rejection. The local Worker/D1 rehearsal passes with three eligible fixture records, one duplicate, and one excluded record; import reports 2 imported/1 skipped because one URL already exists, reimport reports 0 imported/3 skipped, and the existing record's copy/read state remains unchanged. These checks establish converter behavior on fixtures only. They do not read or migrate the owner's vault, so review, production import, and retirement of the prototype flow remain pending.
