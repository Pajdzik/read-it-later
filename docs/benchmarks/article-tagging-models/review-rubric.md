# Tagging-only review rubric

Frozen before the 30-case model evaluations. Production generation remains disabled throughout the comparison. The user removed the earlier 100-call experiment cap; production daily attempts remain independently bounded.

Review the exact source text sent to the model, not an imagined complete article. A useful tag set covers the main subject with concise English topics that help organize and retrieve the article. Synonyms, standard abbreviations, reasonable broader topics and related concepts are acceptable; exact wording or literal source-word overlap is not required. For example, password can be a related topic for a passkey article without being a factual hallucination. An invented specific domain or an unrelated subject is misleading. A broad category may supplement specific tags; an entire set of generic categories is not useful.

Record every returned tag as central, related, too_broad, or misleading, with an English judgment and source-based explanation. Also record coverage as good, partial, or poor and whether the complete set is useful. Partial coverage is acceptable if the main subject remains recognizable. A useful set contains at least one central tag, contains only central/related tags, and is entirely English. Technical names, protocol names and English abbreviations are acceptable English tags.

The representative release gate requires at least 27 useful complete sets across the frozen 30 articles (25 English archive excerpts and five original Polish articles). Every accepted tag must have an English judgment. Up to three unusable or structurally rejected cases may occur; rejected output must never be accepted or salvaged. Any non-English accepted tag, request outside the 8 KiB/192-token limits, missing/stale review, or accepted malformed output blocks the gate. Descriptions have no generated role in this tagging-only release and cannot fail the tagging gate.

Development cases are six public excerpts disjoint from the evaluation corpus. Review development probes before running full evaluations. Provider access/billing failures measure availability, not semantic quality. The first GLM smoke call exposed an overly strict envelope adapter rejecting an empty tool_calls array; its original raw result and classification are retained and explained. No model JSON fields were repaired or discarded. Exact schema validation remains in force.
