# Article tags and fallback descriptions

Tags and descriptions are editable in article details. Tag chips and the tag picker filter the reading list together with search and read state. Tags are normalized with Unicode NFKC, lowercase, and collapsed whitespace. Owner edits permit ten tags of at most forty Unicode characters. Generated descriptions are labeled separately.

## Current candidate: tagging only

The November 4, 2026 comparison recorded **30/30 useful English tag sets** from `@cf/zai-org/glm-4.7-flash` on the frozen 25-English/5-Polish public corpus, with recorded agent judgments. GLM also passed all six disjoint public development cases; the 1B baseline failed all six. This was an offline evaluation, not a live staging run. GPT-6 Luna was blocked by AI Gateway billing and remains unassessed. See the [complete comparison, review rubric, accounting and operating instructions](benchmarks/article-tagging-models/README.md).

Production automatic tagging was enabled on November 12, 2026. It makes one **tagging-only** request for new article saves, preserving supplied/extracted descriptions and the meaningful Markdown prose fallback; it does not generate descriptions. Exact tag-only output, complete 8 KiB serialized request and 192-token completion limits, manual-edit protection, new-saves-only behavior, daily attempts, retries and lease fencing remain enforced. Articles saved before activation are not automatically backfilled.

GLM is the sole application model. Alternative model adapters and the historical combined-generation implementation live only under `benchmarks/`, outside application imports. Their reports and reproduction commands remain available; there is no model fallback or automatic comparison traffic.

The [November 5 Gemma 4 evaluation](benchmarks/article-tagging-gemma/README.md) passed the same tagging-only gate at 28/30 useful sets, versus GLM's recorded 30/30. Gemma's two generic Polish sets and higher estimated cost support retaining GLM; GLM remains the production model.

The revised tagging gate requires at least 27 useful complete tag sets across thirty cases, English consistency, current exact-request/output review bindings, and strict rejection of malformed output. Synonyms and reasonable related concepts count; generated descriptions no longer block tagging. Up to three unusable/rejected cases are allowed if rejected output is never accepted; any accepted non-English tag or invalid output fails the gate. Use `pnpm benchmark:tagging --live --model glm --stage evaluation --output .wrangler/my-tagging-run.json` for a new full evaluation, followed by recorded offline review. The original combined-generation failures below are historical evidence and were not re-scored as passing.

## Configuration and historical combined-generation gate

`ARTICLE_ENRICHMENT_ENABLED` is **true** in production and **false** in staging and default local development. Production and staging have a native Workers AI `AI` binding; default local development has none. Set `ARTICLE_ENRICHMENT_DAILY_LIMIT` to an integer from 0 through 100 (default 100). Zero defers requests without spending inference. The enable switch pauses processing independently of capture, retaining durable pending jobs.

The initial live evaluation on October 31, 2026 (Pacific time) **failed**. On thirty synthetic topic fixtures (fifteen English, fifteen Polish), the configured `@cf/meta/llama-3.2-1b-instruct` produced **0/30 usable schema-valid responses**. Responses frequently exceeded the tag limit, omitted required fields, or ran out of output tokens. Follow-up system/user-message probes returned 0/4 valid responses. The available `json_object` diagnostic returned malformed multiple objects; the earlier statement that the provider rejected the probe was inaccurate. The model is not listed as supporting enforced [JSON mode](https://developers.cloudflare.com/workers-ai/features/json-mode/). The implementation uses system/user messages and application validation, and never silently accepts or repairs malformed output.

The initial thirty calls used 9,659 input and 4,854 output tokens, with median latency 1,189 ms and p95 latency 1,795 ms. Gross inference cost was approximately **$0.00124**, before Cloudflare's shared daily allowance. This is an inference cost calculation from reported token usage, not an account invoice. See the [recorded results](benchmarks/article-enrichment-1b.json) and [fixtures](../benchmarks/enrichment-fixtures.json). These are synthetic article excerpts, not an evaluation of the owner's real library. No private library data was read or sent.

The November 1, 2026 (Pacific time) follow-up also **failed**. Sixty new synthetic diagnostic calls used 12,149 input and 5,189 output tokens, with median latency 653 ms, p95 1,411 ms, and estimated gross inference cost **$0.001371012**. These totals include invalid responses and remain separate from the historical calls above. Across different isolated/combined tasks, 12/60 responses were structurally valid; that is not a library-quality score. All sixteen isolated description attempts failed. The exact production-request probe returned 2/4 valid responses, but both cases requiring generated descriptions failed, and the Polish passkey set added an unsupported password tag. A schema-valid generated description from a different variant invented an efficient-storage claim. See the [summary, complete raw results and agent reviews](benchmarks/article-enrichment-quality/README.md).

Plain article text reduced input-field copying compared with JSON-shaped article data, so the paused production candidate uses that simpler format and at most five evidence-matched existing tags. Separate user/assistant examples, a small vocabulary and explicit language instructions did not establish adequate combined quality. These bounded experiments do not prove that the model can never work.

At the time of the combined-generation investigation, the agreed representative corpus was frozen: [25 unique English excerpts from the public Kamilpedia archive and five original Polish articles](../benchmarks/enrichment-library-fixtures.json), with pinned source revisions, supplied metadata and content hashes. It was **not run for that combined request**, because the small combined probes failed. The later tagging-only evaluation is recorded above. That historical investigation did not establish a representative passing gate.

The original combined-generation gate required at least 27 relevant **complete tag sets** across that 30-case corpus, English consistency for every accepted tag, grounded descriptions in the article language throughout, and rejection of structurally invalid output. Generated descriptions must be one sentence and present in designated generation cases. Existing extracted prose may contain several sentences and retains its fallback priority. Both English and Polish generation paths must also pass reviewed combined diagnostics using the same production source. This gate conservatively requires schema-valid output for every evaluation case. No keyword, ASCII-only test, mocked test or missing review can satisfy it.

Run diagnostics and review offline using the [operating instructions](benchmarks/article-enrichment-quality/README.md). `pnpm benchmark:enrichment --live` now targets the frozen representative corpus, spends thirty calls without retries, and writes `.wrangler/enrichment-evaluation.json`. `--probe` makes four synthetic combined requests with the exact production builder. That phase stopped at 60/100 allowed calls. The user subsequently removed the task cap; tagging-only experiments use a separate append-only ledger with no fixed maximum. Production daily limits remain unchanged. The harness reserves calls durably before dispatch, preserves uncertain attempts, never overwrites a previous live report, and always exits nonzero until recorded semantic review passes. It never reads production D1, deploys a Worker or changes the enable switch. Automated checks disable remote bindings.

## Processing and cost controls

New inserts made while enabled record intent and their enrichment job in the article-save transaction. Duplicate saves, older articles, and imports receive no new intent. The queue transports `{version:1,kind:"enrichment",articleId}` alongside unchanged legacy extraction messages. Hourly recovery repairs missed notifications, materializes missing jobs, and recovers expired leases. Terminal jobs remain until deletion, preventing implicit regeneration.

Enrichment waits for extraction to finish. A reviewed browser clip sends owner-only `enrichAfterCopy:true` on creation so inference cannot race its separate Markdown PUT. Such jobs wait for a saved copy, including manual recovery of a failed copy upload. Link-only saves and terminal extraction failures can use meaningful supplied metadata; hostname/path placeholders are skipped. No enrichment path fetches the source or publishes to an integration.

Existing supplied/extracted descriptions win. Otherwise the processor tries the first meaningful prose paragraph from saved Markdown; generated descriptions remain disabled in the current tagging-only release. The tagging-only request asks for two to four English tags, allowing at most five, and prefers up to five existing library tags whose whole words occur in the available evidence. It adds no unrelated popular tags to fill the vocabulary. Responses may contain fewer tags when evidence is weak. Previously generated descriptions used a 280-character/500-UTF-16-unit envelope. The current model output schema permits only tags. A link-only save cannot acquire an invented description from its title.

Before sanitization, preprocessing reads at most the first 32 KiB UTF-8 of saved Markdown and uses linear delimiter scanners so malformed copies cannot cause quadratic CPU work. The complete logical prompt is bounded to 8 KiB UTF-8, including message roles, JSON escaping, instructions, examples when tested, and vocabulary, and output is limited to 192 tokens. The model is called through the native binding without an SDK, vector index, or added service. At the GLM-4.7-Flash rates of $0.0605/M input and $0.40/M output tokens, 1,500 input plus 150 output tokens costs about $0.151 per thousand requests, before the 10,000-neuron daily allocation shared with other account usage. Extraction, D1, queue, and existing hosting costs are additional. [Cloudflare pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/).

Before each call, a D1 transaction reserves a daily attempt and increments the claimed job's attempts. Reservations are not refunded for provider failures, timeouts, crashes, or uncertain outcomes. Duplicate deliveries cannot exceed the shared allowance. Excess work is deferred to the next UTC day without consuming a retry. Transient failures receive one retry; malformed output is terminal. A successful article never regenerates after ordinary edits, recaptures, or duplicate saves.

Claims use lease tokens and expiry. The job records a fingerprint of the complete model request (including messages and generation parameters) and the copy revision. Completion checks the current copy revision and metadata snapshot in a transaction, discarding changed/deleted inputs and fencing expired/replaced leases. Manual tag edits and description edits—including clearing—are protected. An explicit metadata-refresh recapture retains its existing owner-authorized behavior, and undo restores description provenance with the rest of its snapshot.

Logs contain article IDs, stable status/error codes, attempts, latency, bounded prompt bytes, and provider token usage when available, including rejected model output. They contain no article text, prompts, URLs, or provider exception messages. Inspect `article_enrichment_jobs` for failures, `enrichment_daily_usage` for reserved calls per UTC day, and oldest indexed pending jobs for backlog. Operational jobs, counters, leases, and intent are not portable article data.

## API and backups

- Article DTOs add `tags`, `descriptionOrigin` (`manual`, `extracted`, `generated`, or null), and `tagsManuallyEdited`. List/detail responses include optional compact `enrichment` status. Tags and statuses load in batches.
- Owner PATCH supports `tags` alongside existing metadata. Provenance and protection cannot be patched directly. Capture tokens cannot edit tags, metadata, provenance, or reviewed-copy waiting intent.
- Authenticated `GET /api/tags` returns `{tags:[{tag,count}]}`. `GET /api/articles?tag=...` matches a normalized exact tag and combines with existing search/read-state filters and cursors.
- JSON and ZIP `library.json` exports use v3, retaining copies, tags, provenance, and protection flags. v1/v2 imports remain supported; restoration never schedules enrichment. Existing nonempty descriptions migrate as protected/manual.
- GitHub frontmatter v2 preserves the same metadata. The converter and identity reconciler still accept v1. New tags change the portable Markdown fingerprint, so an existing GitHub backup becomes outdated until the owner explicitly saves it again.

The original feature requires migration `0012_article_enrichment.sql`; this activation adds no migration. The migration also extends existing recapture snapshots so in-flight recovery and undo remain compatible. No backfill is included in production activation.
