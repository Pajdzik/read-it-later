## Findings at the reviewed revision

Severity reflects the access required and the consequence for a single-owner library. Production impact depends on the deployed configuration. Source references point to the reviewed revision.

### 1. Medium · Anonymous sign-in requests can exhaust database capacity

Every request that starts GitHub sign-in creates a fresh OAuth state row in D1 and runs an expired-state cleanup query. The ten-minute expiry limits a row's useful life. It places no bound on the number of live rows or writes. A public client can consume database capacity without a GitHub account, potentially delaying sign-in and other library operations. A rate limit configured independently at the edge could reduce this exposure. [OAuth entry point and state creation](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/auth/handler.ts#L63)

**Fix and verify.** Limit sign-in starts per client and across the application before allocating state. Confirm that starts over the limit leave D1 untouched and ordinary sign-ins still receive a fresh, one-use state.

### 2. Medium · Signing out can redisplay a private extension capture

An unfinished extension capture stores the clipped Markdown in the tab's session storage. Duplicate review can also store the existing library copy there. Explicit sign-out clears two other draft keys and leaves the extension record behind. After navigation, startup restores that record before checking the session and can reopen the capture dialog with the clipped text. Someone using the same open tab can see the clip after logout. Any retained duplicate-review snapshot is also readable from that tab's storage. [Draft and conflict data](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/web/app.ts#L3183) · [Sign-out cleanup](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/web/app.ts#L4447) · [Draft recovery](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/web/app.ts#L3082) · [Startup order](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/web/app.ts#L4853)

**Fix and verify.** Clear extension capture data and conflict snapshots on explicit logout. Keep draft handoff across an intentional sign-in separate from logout. Cover a dismissed duplicate review followed by sign-out and reload. Check both the visible dialog and session storage.

### 3. Medium · Deleting audio or its article leaves the transcript in D1

Audio preparation stores the narration twice, once on the episode and again across its chunks. Deleting the article or removing its audio marks the episode deleted. Cleanup removes the R2 objects and then clears the database cleanup marker. The narration, chunk text, title, author and original URL remain in the active database, accessible to database readers and included in subsequent database-level exports. The existing deletion test confirms that feed access stops and the R2 object disappears. [Stored episode and chunks](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/audio/jobs.ts#L419) · [Article deletion trigger](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/migrations/0002_audio.sql#L27) · [Audio removal](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/audio/jobs.ts#L470) · [Cleanup completion](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/audio/jobs.ts#L1179) · [Existing test](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/tests/podcast.test.ts#L134)

**Fix and verify.** After durable object cleanup succeeds, delete the episode row and let the foreign key cascade to its chunks. Sweep previously deleted episodes, including those with a cleared marker. Cover both deletion paths, a failed cleanup followed by a retry, removal of transcript rows, and preservation of aggregate billing records.

### 4. Medium · Credentials survive a change of library owner

GitHub sign-in checks the configured owner ID when it issues a session. Later session, capture-token and podcast-token checks use credential hashes without checking which owner received them. On a handover that reuses D1, an old session keeps owner access until expiry or revocation. The handover instructions call for revoking sessions and capture tokens but omit the podcast credential. Following those instructions can leave the previous subscriber able to retrieve future episodes indefinitely. [Session issuance](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/auth/handler.ts#L103) · [Session lookup](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/auth/core.ts#L48) · [Capture-token lookup](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/auth/core.ts#L110) · [Podcast-token lookup](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/audio/feed.ts#L67) · [Handover instructions](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/README.md#L102)

**Fix and verify.** Include the podcast token in the handover procedure immediately. Bind each credential to the owner who received it or to a credential generation that changes on handover. Define a migration for existing credentials and verify that all three old credential types lose access after an owner change.

### 5. Medium · A save-only token can create a lasting extraction backlog

The capture API admits 60 requests per token per minute and requests extraction by default. Each eligible new URL can create a durable job. There is no limit on outstanding work attributable to the token, and production processes one extraction message at a time. A lost token or runaway shortcut can delay the owner's captures and consume queue, storage and conversion resources. Revocation stops new submissions. Existing jobs carry no token identity, and hourly recovery republishes pending jobs, adding queue traffic while a backlog persists. [Token rate limit](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/auth/core.ts#L119) · [Capture defaults](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/articles/handler.ts#L217) · [Job creation](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/articles/repository.ts#L219) · [Production queue](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/wrangler.jsonc#L166) · [Recovery publisher](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/articles/processor.ts#L128)

**Fix and verify.** Record the originating credential and enforce outstanding-work limits atomically when creating jobs. Bound recovery publication and provide a way to cancel the outstanding work of a revoked token. With a small test quota, verify that a saturated token cannot consume capacity reserved for owner-initiated work.

### 6. Medium · Library browsing repeatedly processes untrusted Markdown

With audio enabled, each library page fetches the full Markdown of every displayed copy and synchronously recalculates podcast suitability. The normal page contains up to 50 articles. The HTML-removal expressions can rescan overlapping portions of malformed text, so work can grow quadratically within a single copy. An externally sourced article must first enter the library. Once stored, it can repeatedly slow or interrupt ordinary library reads without anyone requesting narration. The production configuration enables this path. [Library page size](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/web/app.ts#L1260) · [List handler](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/articles/handler.ts#L269) · [Full-copy query and loop](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/audio/jobs.ts#L183) · [HTML removal](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/audio/jobs.ts#L58) · [Production audio setting](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/wrangler.jsonc#L137)

**Fix and verify.** Use a bounded, linear parser and store the suitability result by copy revision. Backfill older revisions outside the listing request. Verify that listing reads only summaries and that changing a copy invalidates its prior result.

### 7. Medium · Podcast descriptions disclose the complete original URL

An episode snapshots the article's submitted URL and includes it verbatim in the RSS description. A saved private share link can carry an access credential in its path, query or fragment. A podcast client or service holding the feed URL then receives a separate capability to the source document. Rotating the podcast feed cannot revoke that source link. The feed already supplies an owner-authenticated Potem reader link for each episode. [Submitted URL handling](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/articles/validation.ts#L11) · [Episode snapshot](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/audio/jobs.ts#L420) · [RSS output](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/audio/feed.ts#L35)

**Fix and verify.** Use the Potem reader link and, when attribution is wanted, the publisher hostname. Apply this at feed rendering so existing episodes benefit. Verify with a synthetic private-link marker that source credentials are absent from the entire RSS response.

### 8. Low · Capture handoffs put private source details in request URLs

The bookmarklet puts the source page's full address, including any fragment, and its title in the query of the initial Potem navigation. The installed app's share target also sends shared text, title and URL by GET. The browser sends these fields before the owner confirms the save. Removing the query from browser history afterward cannot retract it from infrastructure that records request URLs. Worker observability has query redaction enabled. Retention by other logging layers is deployment-dependent. [Bookmarklet handoff](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/web/capture.ts#L9) · [Share target](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/web/manifest.webmanifest#L11) · [History cleanup](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/web/app.ts#L4793) · [Observability configuration](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/wrangler.jsonc#L235)

**Fix and verify.** Pass bookmarklet metadata through the existing origin-checked message exchange and accept the share target's data in a POST body. Verify that a canceled capture with synthetic private fields puts none of them in navigation or subresource request URLs.

## Authentication and deployment hardening

- **Bind OAuth codes to the initiating transaction with PKCE.** Potem validates one-use browser-bound state, the client secret and the owner ID. Its authorization request omits an S256 challenge and the token exchange omits the corresponding verifier. This leaves a gap if an unused owner authorization code is independently exposed. Add a fresh verifier per login, store it with the expiring state and require the matching exchange. [Authorization parameters](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/auth/handler.ts#L66) · [Token exchange](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/src/auth/handler.ts#L89) · [GitHub OAuth guidance](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps#web-application-flow)
- **Lock the actions that run in the production deployment job.** Checkout, pnpm setup and Node setup use mutable major-version tags. A compromised upstream release could change code running on the same runner that later receives Cloudflare deployment credentials. Pin verified action commits or adopt a workflow dependency lockfile, and review updates through pull requests. [Deployment workflow](https://github.com/Pajdzik/read-it-later/blob/23bfcea9aa6c6fe87765595a9c2e188cac52431c/.github/workflows/checks.yml#L173) · [GitHub Actions security guidance](https://docs.github.com/en/actions/reference/security/secure-use#using-third-party-actions)

## Scope of the original review

The review covered the web app and extension, Worker routing and credentials, article and feed capture, queues, podcast delivery, archives and PDFs, integrations, and the checked-in deployment workflow. Seven targeted tests passed against local Worker, D1 and R2 fixtures, covering owner and CSRF checks, podcast token rotation and deletion, PDF access, and archive restoration. Eight CI change-detection and build-routing tests also passed. The report draws on source inspection for the findings. It does not measure outage thresholds or establish that any information was accessed in production.

The live Cloudflare account, edge rules, bucket visibility, retained logs and deployed image were outside the review. The most relevant deployment checks are whether a sign-in rate limit already exists, which systems retain complete request URLs, and which package versions are present in the deployed image.
