# Mobile release validation

Status: automated local mobile rehearsal and read-only deployed checks recorded October 6, 2026. Automated and physical-device results are recorded separately. M06 and M08 remain pending until their physical-device and deployed acceptance checks pass.

## Automated scope

`pnpm test:mobile` runs Playwright touch flows with Android Chromium and iPhone WebKit profiles against a fresh temporary local Worker/D1. CI installs both browser engines. The existing `pnpm test:browser` desktop smoke remains a separate check.

The runner covers anonymous sign-in, Add/save and duplicate handling, reading a saved Markdown copy, explicit read/unread across reload, search/filter navigation, settings, dialog close/recovery, long titles/URLs, narrow portrait and short landscape layouts, and wide reader content. It verifies failed-save draft retention, ambiguous shared text, logged-out `/add` recovery, and that GET share-target navigation never saves before confirmation. With background extraction disabled in the local configuration, it verifies a successful queued-save acknowledgment, the visible paused status, the pending reader, and manually saving a copy for reader/layout/read-state checks. It does not fetch the local source fixture for automatic extraction or exercise real OAuth.

It derives share-navigation names from the manifest, validates referenced icon responses and PNG dimensions, waits for service-worker activation and a populated public cache, and checks that private API responses are `no-store` and absent from caches. It also exercises local capture-token success, duplicate, explicit link-only opt-out, and revocation using a temporary token. The token checks require the default response to report `extractionRequested: true`, verify the owner status shows a persisted queued intent while the processor is paused, and confirm that no copy or job history is returned synchronously. They validate the HTTP contract, not the iOS Shortcuts app. The runner uses dummy auth settings and removes its temporary database, tokens, processes, and browsers after the run.

The existing production URL is `https://read-it-later-production.pajdzik.workers.dev`. The read-only public-shell, health, manifest/icon, anonymous API rejection, and cache-header checks are recorded above. For an Android release check, install the app in a browser supporting Web Share Target, share one URL and title into it, confirm no save before review, save the link, inspect pending/paused capture status, and use a manual copy to verify the reader. When the protected processor is enabled, also verify eventual ready/failed status. Check ambiguous text and logged-out draft recovery. Also verify network failure retains the draft and private responses are absent from service-worker caches. Record OS/browser/version, origin, deployed commit, date, and results. Browser emulation does not validate installation, OS Share Sheets, on-screen keyboards, or actual Safari/Chrome device behavior.
